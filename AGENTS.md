# Agent Guidelines for singleCellTK

Instructions for AI coding agents (Claude Code, Copilot, Cursor, and similar) working in this
repository. Human contributors should read [`CONTRIBUTING.md`](CONTRIBUTING.md); the rules
overlap, but this file emphasizes the ones agents get wrong.

**Read before your first edit:** [`docs/architecture.md`](docs/architecture.md), then
[`docs/adr/`](docs/adr/) 0001-0003. If you are adding a function, follow
[`docs/adding-a-new-tool.md`](docs/adding-a-new-tool.md) step by step.

---

## What this package is

An R/Bioconductor wrapper layer for single-cell RNA-seq analysis. It does not implement
methods; it wraps Seurat, scran, scater, celda, SoupX, SingleR, and Python tools behind one
consistent interface built on `SingleCellExperiment`. 87 files in `R/`, 251 exported
functions, 88 hard dependencies.

**Everything flows through a `SingleCellExperiment`.** Analysis functions take it as their
first argument, add results to it, and return it.

## Hard rules

### Never edit generated files

`man/*.Rd` and `NAMESPACE` are **generated by roxygen2**. Never edit them directly — your
change is silently reverted the next time anyone runs `devtools::document()`.

To change documentation, edit the `#'` roxygen block above the function in `R/`, then run:

```sh
Rscript -e 'devtools::document()'
```

This is the single most common agent error in R packages. `NAMESPACE` looks like a config file
and is not one.

### Never add to `Imports` by reflex

`DESCRIPTION` already carries 88 hard dependencies, and reducing that is active work
([ADR-0005](docs/adr/0005-dependency-policy.md)). A new analysis backend goes in **`Suggests`**
and is gated at the point of use:

```r
if (!requireNamespace("thePackage", quietly = TRUE)) {
    stop("Package 'thePackage' is required for runX(). ",
         "Install it with BiocManager::install('thePackage').")
}
```

Adding to `Imports` requires explicit human sign-off. Do not do it silently as part of a
larger change.

### Never install packages

Not in `R/`, not in `inst/shiny/`, not in a script you write for the user to run without
saying so. `install.packages()` and `BiocManager::install()` write to the user's library.
Check with `requireNamespace()` and report what is missing.

(`inst/shiny/ui.R:1-9` currently violates this. It is a known defect, not a precedent.)

### Never use `set.seed()`

Use `withr::with_seed(seed, { ... })`, which restores the user's RNG state afterwards. The
package currently has **zero** bare `set.seed()` calls, 16 `withr::with_seed()` sites, and 5
`reticulate::py_set_seed()` calls on Python-backed paths. Keep it that way.

### Never claim something works without running it

The package has 88 dependencies and may not be installed in your environment. If you cannot
run `devtools::test()`, say so plainly. Do not describe untested code as verified, and do not
present static analysis as a confirmed bug — `docs-audit/bug-candidates.md` labels all 35 of
its findings **unverified** for exactly this reason, and that labelling must survive.

## Conventions to follow

### The function contract ([ADR-0001](docs/adr/0001-sce-in-sce-out-contract.md))

```r
runMyMethod <- function(inSCE, useAssay = "counts", assayName = "myMethod", ...) {
    selected <- .selectSCEMatrix(inSCE, useAssay = useAssay, returnMatrix = TRUE)
    mat <- selected$mat
    # ... compute ...
    expData(inSCE, assayName, tag = "transformed") <- result
    inSCE <- expSetDataTag(inSCE, "transformed", assayName)
    return(inSCE)
}
```

- First argument `inSCE`; return `inSCE`.
- Validate inputs with `.selectSCEMatrix()` / `.manageCellVar()` from `R/validityFunctions.R`.
  **Do not index `assay(inSCE, useAssay)` or `colData(inSCE)[[var]]` directly** — the helpers
  produce useful error messages and direct indexing produces "invalid subscript".

### Naming ([ADR-0002](docs/adr/0002-function-naming-families.md))

Prefixes: `run*` (analysis), `plot*` (visualization), `import*` (ingestion), `get*`/`set*`
(accessors), `export*` (egress), `report*` (HTML).
Arguments: inputs are `use*` (`useAssay`, `useReducedDim`), outputs are `*Name` (`assayName`,
`reducedDimName`).
Every exported function needs a `@family` tag.

**Before adding a new exported function, check whether an existing dispatcher should gain a
`method =` option instead.** `runNormalization()`, `runDimReduce()`, `runBatchCorrection()`,
and `runCluster()` are all multi-backend. Extending one is usually correct; adding a parallel
export usually is not.

### Result storage ([ADR-0003](docs/adr/0003-result-storage-and-tagging.md))

| Result shape | Goes in |
|---|---|
| matrix, same dims as input | `assay` — **and must be tagged** |
| per-cell value | `colData` |
| per-feature value | `rowData` |
| cells × k embedding | `reducedDim` |
| anything else | `metadata(inSCE)$sctk$<functionName>` |

The tag vocabulary is **closed**: `"raw"`, `"normalized"`, `"scaled"`, `"batchCorrected"`,
`"transformed"`, `"uncategorized"`. A tag describes the *kind of data*. Never use the assay's
own name as its tag.

### Tests ([ADR-0006](docs/adr/0006-testing-strategy.md))

Every new exported function gets a test in the same change. For `run*` functions, assert the
four contract properties: returns an SCE, the named output exists, dimensions are preserved,
the output is tagged. Use `data(scExample, package = "singleCellTK")` as the fixture — never
`importExampleData()`, which needs network access. Add `skip_if_not_installed()` for any gated
dependency.

### R style

- `seq_len(n)` / `seq_along(x)`, never `1:n` — `1:0` is `c(1, 0)`
- `vapply()` with an explicit `FUN.VALUE`, never `sapply()` in package code
- `TRUE` / `FALSE`, never `T` / `F`
- `drop = FALSE` on any matrix subset that might select one row or column
- `inherits(x, "class")`, never `class(x) == "class"`
- Qualify third-party calls: `scran::quickCluster()`

## Repository-specific requirements

### Log every prompt

**Every prompt given to an agent working on this repository is appended verbatim to
[`prompts.md`](prompts.md)**, unedited, in the order received. This keeps the provenance of
agent-authored changes traceable — anyone reading a commit can see what was actually asked.

If you are an agent and you have just been given a prompt, append it before or alongside the
work it triggers.

### Record decisions as ADRs

Architecturally significant decisions — anything constraining what future contributors may do
— go in [`docs/adr/`](docs/adr/) using the format in
[ADR-0000](docs/adr/0000-record-architecture-decisions.md). Do not edit an accepted ADR to
change its decision; write a new one that supersedes it.

Be honest in the **Consequences** section about what gets harder. An ADR listing only benefits
is not recording a decision.

### Check the audit before reporting a problem

[`docs-audit/`](docs-audit/) contains a July 2026 static audit: 35 bug candidates, a
dependency inventory, article and roxygen coverage findings. If you think you have found a
problem, check whether it is already recorded there. If it is, add evidence rather than a
duplicate report.

## Verification commands

```sh
Rscript -e 'devtools::document()'                  # after any roxygen change — REQUIRED
Rscript -e 'lintr::lint("R/yourfile.R")'           # single file; no package load needed
Rscript -e 'devtools::test(filter = "topic")'      # needs the package installed
Rscript -e 'devtools::check()'                     # full R CMD check
Rscript -e 'BiocCheck::BiocCheck()'                # Bioconductor conventions
```

`roxygen2` and `lintr` work without the full dependency tree. Everything else needs the
package installed.

## Known traps in this codebase

| Trap | Detail |
|---|---|
| `.testFunctions()` at `R/miscFunctions.R:146` | Dead code that exists to suppress a `R CMD check` NOTE. Do not "fix" it by adding more references. It is scheduled for deletion. |
| `docs/` is a tracked build output | The pkgdown site is committed. Hand-written docs also live under `docs/`. Do not confuse them. |
| Articles are not checked | `vignettes/articles/` is excluded from the tarball, so `R CMD check` never sees it. Defects there accumulate silently — review changes carefully. |
| `.travis.yml` is dead | GitHub Actions in `.github/workflows/` is the live CI. |
| `DESCRIPTION` says `R (>= 4.0)` | Stale. Bioconductor 3.20 requires R >= 4.4. |
| The only shipped vignette is a stub | `vignettes/singleCellTK.Rmd` is 102 lines of pointer. Real content is in website-only articles. |
