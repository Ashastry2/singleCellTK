# Contributing to singleCellTK

Thanks for contributing. This document covers setup, conventions, and what a reviewable change
looks like.

> **This is the `Ashastry2/singleCellTK` fork.** It diverges from
> [`compbiomed/singleCellTK`](https://github.com/compbiomed/singleCellTK), the Bioconductor
> upstream. Issues and pull requests here concern *this* fork. If your change is a general
> improvement that upstream would want, consider opening it there too — but this repository's
> workflow is its own.

## Setting up

**Requirements.** R >= 4.4 (Bioconductor 3.20+). Note that `DESCRIPTION` currently declares
`R (>= 4.0)`; that floor is stale and does not reflect what the package actually needs.

```sh
git clone https://github.com/Ashastry2/singleCellTK.git
cd singleCellTK
```

```r
install.packages(c("devtools", "BiocManager", "roxygen2", "lintr", "testthat"))
BiocManager::install("BiocCheck")
devtools::install_deps(dependencies = TRUE)   # slow: 88 hard dependencies
devtools::load_all()
```

The dependency install is genuinely slow — expect the better part of an hour on a cold
library. [ADR-0005](docs/adr/0005-dependency-policy.md) is about fixing that.

**Python tools** (scanpy, scrublet, bbknn, scanorama) are optional. If you need them:

```r
sctkPythonInstallConda()      # or sctkPythonInstallVirtualEnv()
selectSCTKConda()
```

You can develop and test everything else without a Python environment —
`reticulate::import(delay_load = TRUE)` means the bindings are not touched until first use.

## Branching and commits

- Branch from the working branch, named `feature/short-description` or `fix/short-description`.
- Write commit messages that explain **why**, not just what. The diff already shows what.
- Keep commits focused. A commit that adds a function and also reformats an unrelated file is
  hard to review and harder to revert.

## Conventions you must follow

These are not style preferences — they are contracts, each with an ADR behind it:

1. **[ADR-0001](docs/adr/0001-sce-in-sce-out-contract.md)** — analysis functions take `inSCE`
   first and return it. Validate inputs with `.selectSCEMatrix()` and `.manageCellVar()` from
   `R/validityFunctions.R`, never by indexing directly.
2. **[ADR-0002](docs/adr/0002-function-naming-families.md)** — use an established prefix
   (`run*`, `plot*`, `import*`, `get*`, `export*`); inputs are `use*`, outputs are `*Name`;
   every export carries a `@family` tag.
3. **[ADR-0003](docs/adr/0003-result-storage-and-tagging.md)** — results go in the slot
   matching their shape; every assay written is tagged with `expSetDataTag()` using a tag from
   the closed vocabulary.
4. **[ADR-0005](docs/adr/0005-dependency-policy.md)** — new dependencies go in `Suggests` and
   are gated with `requireNamespace()`. Adding to `Imports` needs justification in the PR.
5. **[ADR-0006](docs/adr/0006-testing-strategy.md)** — every new exported function ships with
   a test in the same PR.

### Things that are always wrong

- **Hand-editing `man/*.Rd` or `NAMESPACE`.** Both are generated by `devtools::document()`.
  Your edit will be silently reverted.
- **`set.seed()`.** Use `withr::with_seed()`, which restores the user's RNG state.
- **`1:n`.** Use `seq_len(n)` / `seq_along(x)`. `1:0` is `c(1, 0)`, which iterates backwards.
- **`sapply()` in package code.** Use `vapply()` with an explicit `FUN.VALUE`, or `lapply()`.
- **Bare `T` / `F`.** They are rebindable variables. Use `TRUE` / `FALSE`.
- **Matrix subsetting without `drop = FALSE`** where the result may have one row or column.
- **`install.packages()` anywhere in the package or the Shiny app.** Never install into a
  user's library on their behalf.

## Before you open a pull request

```r
devtools::document()                        # regenerate man/ and NAMESPACE
lintr::lint_package()                       # should not increase the lint count
devtools::test()                            # or filter = "yourtopic" while iterating
devtools::check()                           # R CMD check
BiocCheck::BiocCheck()                      # for release-bound changes
```

### PR checklist

- [ ] Follows the ADR contracts listed above
- [ ] `devtools::document()` run; `man/` and `NAMESPACE` regenerated, not hand-edited
- [ ] Tests added and passing
- [ ] `devtools::check()` produces no new warnings or notes
- [ ] New exports added to `_pkgdown.yml`
- [ ] User-facing changes noted in `NEWS.md`
- [ ] Any new dependency justified per ADR-0005

## Documentation changes

[ADR-0004](docs/adr/0004-documentation-architecture.md) governs which surface gets what:

| Surface | For |
|---|---|
| Roxygen (`R/*.R`) | What a function does, exactly |
| `vignettes/singleCellTK.Rmd` | The canonical end-to-end workflow. Ships in the tarball, so `R CMD check` runs it. |
| `vignettes/articles/*.Rmd` | Task-focused how-tos, GUI screenshots. Website only — **not** checked by `R CMD check`, so review them carefully. |
| `README.md` | Pitch, install, quick-start, citation |

Articles use the "Interactive Analysis / Console Analysis" tabset when they cover both
interfaces, open with a `library(singleCellTK)` chunk, state their prerequisites, and qualify
third-party calls (`celda::plotRPC()`).

## Changing a convention

Conventions live in [`docs/adr/`](docs/adr/). To change one, do not edit the ADR — write a new
one that supersedes it, and mark the old one *Superseded by ADR-NNNN*. See
[ADR-0000](docs/adr/0000-record-architecture-decisions.md).

## Reporting bugs

Open an issue with: what you ran (a minimal reproducible example), what you expected, what
happened, and `sessionInfo()`.

Check [`docs-audit/bug-candidates.md`](docs-audit/bug-candidates.md) first — 35 suspected
defects are already catalogued there, unverified. If yours is one of them, saying so with a
concrete reproduction is genuinely valuable: it promotes a suspicion to a confirmed bug.

## Working with AI agents

If you use Claude Code, Copilot, or similar on this repository, read
[`AGENTS.md`](AGENTS.md). It encodes the same rules in a form agents follow reliably, and adds
some that exist specifically because agents get them wrong — regenerating `NAMESPACE` rather
than editing it, and not adding dependencies by reflex.

One repository-specific rule: **every prompt given to an agent is appended verbatim to
[`prompts.md`](prompts.md)**, so the provenance of agent-authored changes stays traceable.
